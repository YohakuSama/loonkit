# 配置托管、更新与覆盖风险

本页说明 **Loon 配置文件的生命周期**：何时开启托管、何时会覆盖本地修改、如何检查更新是否生效。首次部署顺序见[导入指南](./SETUP_GUIDE.md)；DNS、节点选择和诊断由各自专题说明。

## 三个选项分别控制什么

| 选项 | 作用 | 建议 |
| --- | --- | --- |
| **从链接导入** | 从 URL 添加配置文件 | 通过「配置 → 所有配置文件 → ＋」进入；导入后仍需明确应用对应配置。 |
| **托管** | 将配置按远程 URL 管理，界面中出现更新相关选项 | 希望跟随远程配置变更时可启用；离线、自行维护配置可不启用。 |
| **更新频率** | 配置检查更新的间隔 | 只表示检查频率；iOS 不保证后台会在精确时刻执行。 |
| **全覆盖更新** | 以托管内容覆盖本地设置的范围更大 | **日常维护建议关闭**；确有完整重置需求时，在备份并确认影响后才使用。 |

> **覆盖不是合并。** 已有个人节点、订阅、本地编辑或证书等设置的用户，应先确认备份和恢复方案。更换托管选项不会自动修复 DNS 或节点连接问题。

## 首次配置与之后更新的区别

**首次完整部署**：确认已有设置已备份，再导入并应用配置；只有主动接受完整替换后果时才考虑全覆盖。LoonKit 的 `[Proxy]` 与 `[Remote Proxy]` 默认没有个人节点，导入后仍需自行补充。

**日常维护**：保留已添加的个人设置，关闭全覆盖更新；主配置更新后，按需要另行检查远程规则和插件是否已刷新。配置文件更新与规则/插件资源刷新不是同一个动作。

**想改变更新选项**：已核对的长按配置菜单包括「应用、编辑、重命名、启用 iCloud、导出、删除」，**没有「更新策略」**。应以实际 App 的托管配置管理入口为准，避免依赖旧版截图中的菜单名。

## 出现异常时先判断是哪一层

| 现象 | 优先检查 |
| --- | --- |
| 导入后节点消失 | 是否使用了全覆盖、个人订阅是否有备份、当前应用了哪个配置。 |
| 配置版本没有更新 | 托管 URL、更新频率、实际应用的配置文件；不要把后台检查等同于推送。 |
| 规则或插件仍是旧内容 | 远程资源是否分别刷新，版本是否仍引用固定提交。 |
| 解析失败或切换海外 DoH | 转至[DNS 专题](./DNS_PRIVACY.md)核对 **DNS 服务器**、DoH 流量模式与查询回落；不在托管页面调整这些逻辑。 |
| 节点能连、服务不能用 | 转至[节点选择](./NODE_SELECTION.md)、[规则说明](../rules/README.md)及[网络辅助](./NETWORK_DIAGNOSTICS.md)。 |

## 与托管无关的运行配置

现役主配置中的 `disable-stun = true` 与 `udp-fallback-mode = REJECT` 可能影响部分 UDP/STUN 场景；它们不是 DNS 查询回落，也不是全覆盖开关。遇到语音、实时连接或游戏问题，应结合 Loon 请求记录判断，再决定是否调整个人配置。
