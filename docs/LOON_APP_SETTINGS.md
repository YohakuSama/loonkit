# LoonKit · 导入、托管与 App 设置

本文针对仓库中的正式配置，并结合 2026-10-26 核对的 Loon App 界面整理。不同版本的按钮位置可能调整，**不把「长按 → 更新策略」列为已确认的操作路径**。

## 首次完整部署

1. 在 Loon 底部 **配置** 标签页找到 **所有配置文件**。
2. 点击右上角 **＋**，选择 **从链接导入**，填写 [正式版配置 URL](https://raw.githubusercontent.com/YohakuSama/loonkit/main/LoonKit.lcf)。
3. 打开 **托管**。开启后应出现 **更新频率** 与 **全覆盖更新**；可按需设置频率（截图示例为每隔 7 天）。
4. **仅在已经备份、且决定完整替换当前配置时**，开启「全覆盖更新」并确认。该操作可能覆盖既有节点、订阅、证书及其他本地设置。
5. 确认当前应用 `LoonKit.lcf`；再导入个人节点订阅并为各策略组选路。

> 当前主配置 `[Proxy]` 与 `[Remote Proxy]` 均未预设节点。已有大量个人设置的用户应先确认恢复方案，避免覆盖不可恢复的数据。

## 日常托管更新

- 初次完成之后，**关闭全覆盖更新**，由个人需求决定更新频率。
- 在已核对的 Loon 界面中，**长按配置文件菜单是「应用、编辑、重命名、启用 iCloud、导出、删除」**，没有「更新策略」。因此，不能把「长按 → 更新策略」作为准确路径。若需要修改托管设置，应检查当前配置的远程管理/编辑入口，或重新进入对应的「从链接导入」选项，避免不经备份就覆盖原配置。
- 配置文件更新与远程插件/规则刷新不完全相同；主配置更新后应检查远程规则和插件版本。
- iOS 不保证 Loon 在后台按指定时刻执行所有更新。更新频率反映检查策略，不等于云端强制推送。
- 如果新版升级修改了策略结构，先阅读 [更新记录](./CHANGELOG.md) 并备份，再按需重新全覆盖。

## DNS 服务器、DoH 流量模式与查询回落

**配置 / 设置 → DNS → DNS 服务器** 中需要区分三项：

| 项目 | 使用建议 |
| :--- | :--- |
| **DoH 服务器** | 默认 AliDNS 适合主要在中国大陆网络使用。也可以换为自己的 DNS，或在中国大陆有稳定接入、按需要确认支持 ECS 的解析服务；更换时使用服务商提供的完整 DoH HTTPS URL。 |
| **DoH 流量模式** | 默认 AliDNS 能直连时保留 `DIRECT`。若换为**需要通过代理访问的海外 DoH**，切换为 **`RULE`**，并确认其域名/IP 实际匹配可用代理规则；`RULE` 本身并不保证网络可达。 |
| **查询回落** | 隐私优先时可关闭，限制 Loon 在加密 DNS 失败后使用普通 UDP DNS；但 DoH 不可达时可能无法解析。旧版「加密 DNS 失败回退到普通 DNS」对应这项功能，并非 DoH 路由模式。 |

上述 App 设置需要与托管的 `[General]` DNS 配置一起核对；重新导入或全覆盖更新后应确认生效值。节点独立的 `server-dns`、应用自己的 DoH/DoT 不由「查询回落」统一控制。

操作细节、AliDNS 启动 Host 和测试顺序见 [DNS 设置与连通性检查](./DNS_PRIVACY.md)。

## 其它功能的适用条件

| 项目 | 对本配置的建议 |
| :--- | :--- |
| **规则分流** | 推荐启用，避免全局直连绕过预期分流。 |
| **`Proxy` / `Auto` / `Fallback`** | 添加自己的节点订阅，并分别为自动测速与备用组筛选候选。 |
| **脚本与插件** | 使用网络辅助时确认启用。脚本用于执行实际诊断。 |
| **MitM / 复写** | 网络诊断插件不依赖它们；其他插件确有要求时再配置。 |
| **DNS 域名拦截** | 当前为 `DNS + LOOPBACKIP`，不是「查询回落」。 |
| **TUN Only、QUIC、IPv6、UDP** | 按实际网络、节点协议与应用兼容性调整，不照搬旧知识库截图一律开启。 |

默认策略组中 Apple、Microsoft、Bilibili、Line、Speedtest 优先 DIRECT；**Paypal 默认使用 `Proxy`**。当前 `disable-stun = true` 与 `udp-fallback-mode = REJECT` 会限制某些 UDP/STUN 场景，请先查请求记录而非盲改整套规则。
